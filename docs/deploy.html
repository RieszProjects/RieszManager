部署教程

这一篇是完整的部署说明，包括组件、配置、HTTPS、账号安全、推送通知、升级、备份和排错；只想先跑起来试试的话看快速上手；部署好以后的日常使用见使用指南。

组件与要求

RieszManager由宿主机上的runner和三个Docker容器组成：

组件运行位置说明
runner宿主机（systemd用户服务）读取~/.claude、浏览工作区、启动和驱动claude进程
backendDockerDjango（ASGI/uvicorn），负责登录、两步验证、API与WebSocket代理、推送通知
frontendDocker构建好的静态前端（nginx）
gatewayDockernginx网关，监听RIESZ_BIND:RIESZ_PORT（默认127.0.0.1:18573）

runner和backend容器必须以同一个用户（同一uid/gid）运行：容器通过挂载目录访问runner的Unix socket，socket只对该用户可读写。

部署主机需要满足以下条件：

  • Linux与systemd：systemd用于管理runner的用户服务。
  • Claude Code已安装并登录：在要使用的用户下执行claude能正常对话。
  • Python ≥ 3.10：供runner使用。
  • Docker Engine与Docker Compose v2：运行rieszctl的用户需要能执行docker（加入docker组后重新登录）。
  • 一个TLS终端：Cloudflare Tunnel、Caddy、带证书的nginx等。不要把网关端口直接暴露到公网。

获取代码

克隆仓库并执行init生成初始配置文件：

git clone https://github.com/RieszProjects/RieszManager.git RieszManager
cd RieszManager
./rieszctl init

./rieszctl init会从.env.example生成.env（文件权限600），并自动填入：

  • RIESZ_SECRET_KEY、RUNNER_TOKEN：随机生成的密钥；
  • RIESZ_PASSWORD：随机临时密码，会打印在终端上；
  • RIESZ_UID / RIESZ_GID：当前用户的uid和gid；
  • RUNNER_SOCKET_DIR：~/.local/state/riesz-manager/run；
  • WORKSPACE_ROOT：默认是当前用户的家目录，也可以在初始化时用WORKSPACE_ROOT=/path ./rieszctl init指定。

填写配置

.env同时被Docker Compose、backend容器和宿主机runner读取。打开.env，至少确认下面几项：

变量说明
WORKSPACE_ROOT工作区根目录，其下每个一级文件夹是一个项目
RIESZ_PUBLIC_ORIGIN对外访问地址，如https://claude.example.com（用于CSRF、WebSocket来源校验、安全Cookie）
RIESZ_USERNAME / RIESZ_PASSWORD登录账号；建议改用RIESZ_PASSWORD_HASH，见账号与两步验证
RIESZ_PORT / RIESZ_BIND网关监听地址，默认只监听本机127.0.0.1:18573
RIESZ_TRUST_CF_HEADER使用Cloudflare Tunnel时设为true，以便按真实客户端IP限流
RUNNER_DEFAULT_PERMISSION_MODE新会话的权限模式，见权限模式和模型
RUNNER_ALLOW_BYPASS是否允许在网页中切换到「跳过权限」模式
RUNNER_CHROME网页端会话是否连接Claude in Chrome：auto（跟随你在终端里/chrome的默认设置）、on、off
OPENAI_API_KEY可选，启用服务端语音转写
RIESZ_VAPID_PRIVATE_KEY可选，推送通知的签名密钥；留空时首次使用会自动生成，保存在data/backend/vapid_private.pem

全部变量的详细列表见文末的环境变量参考。

.env中含有$的值（例如密码哈希pbkdf2_sha256$...）必须用单引号包起来，否则会被当成变量展开。

安装runner

在要运行Claude Code的宿主机用户下执行：

./rieszctl runner install

这条命令会做三件事：

  1. 在runner/.venv创建Python虚拟环境并安装依赖；
  2. 写入~/.config/systemd/user/riesz-runner.service并启动服务；
  3. 尝试执行loginctl enable-linger $USER，让用户服务在你注销SSH或主机重启后继续运行（若没有权限，会提示你手动用sudo执行）。

runner默认通过登录shell（$SHELL -lc）启动claude，因此会话里的Bash命令看到的环境变量与你在终端里的一致；若不需要，可以在.env里设置RUNNER_LOGIN_SHELL=false。

常用的runner管理命令：

./rieszctl runner status
./rieszctl runner logs
./rieszctl runner reload      # 应用新代码或修改后的 .env：等所有托管会话空闲后再重载
./rieszctl runner restart     # 立即重启：会中断正在工作的会话

reload会等到runner托管的所有Claude会话都空闲（没有进行中的回合、待确认的权限和排队消息，也没有仍在运行的后台命令、子代理或监视任务）时，才结束这些空闲进程并重新加载自己；会话记录都在磁盘上，下次发消息时会自动恢复。restart则立即生效，正在工作的会话会被打断，一般只在runner卡住时使用。完整子命令还包括start、stop、uninstall和run（在前台直接运行）。

启动容器

构建并启动三个容器，然后检查整体状态：

./rieszctl up
./rieszctl status

./rieszctl status会依次检查runner的socket、容器运行状态，以及网关的健康检查接口http://127.0.0.1:$RIESZ_PORT/api/healthz。后端的SQLite数据库保存在仓库下的data/backend/目录中，用来存放登录记录、两步验证密钥、归档与排序、快捷短语和推送订阅等数据。

日常管理容器的命令：

./rieszctl restart            # 只改了容器相关的 .env 配置时重启容器
./rieszctl up                 # 更新代码后重新构建并启动
./rieszctl down               # 停止容器
./rieszctl logs               # 查看所有容器日志，也可指定服务名如 ./rieszctl logs backend

配置HTTPS

gateway容器只提供HTTP，并且默认只监听本机127.0.0.1:18573。对外提供服务时，需要在它前面放一个TLS终端。下面是三种常见做法。

Cloudflare Tunnel（推荐）

  1. 在Cloudflare Zero Trust后台进入Networks → Tunnels，创建（或选择已有的）隧道，按页面提示在宿主机上安装cloudflared连接器。
  2. 在该隧道的Public Hostname中添加一条规则：Subdomain / Domain填你的域名；Service选HTTP，URL填localhost:18573（与RIESZ_PORT一致）。
  3. 在.env中设置RIESZ_PUBLIC_ORIGIN=https://你的域名和RIESZ_TRUST_CF_HEADER=true，然后执行./rieszctl restart。

WebSocket会自动透传，无需额外配置。如果你希望进入登录页之前再加一层验证，可以在Cloudflare Access中为这个域名配置策略。

Caddy

在Caddyfile中加入：

claude.example.com {
    reverse_proxy 127.0.0.1:18573
}

Caddy会自动申请证书并设置X-Forwarded-Proto头。记得把.env里的RIESZ_PUBLIC_ORIGIN设为https://claude.example.com并重启容器。

已有的nginx

如果主机上已经有nginx并配好了证书，添加如下站点配置（注意转发WebSocket所需的Upgrade与Connection头，以及长连接超时）：

server {
    listen 443 ssl http2;
    server_name claude.example.com;
    ssl_certificate     /path/fullchain.pem;
    ssl_certificate_key /path/privkey.pem;
    client_max_body_size 210m;
    location / {
        proxy_pass http://127.0.0.1:18573;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 1d;
    }
}

账号与两步验证

  • 修改密码：在宿主机执行./rieszctl hash-password，按提示输入新密码，把输出的RIESZ_PASSWORD_HASH='...'写入.env，删除或清空RIESZ_PASSWORD，然后执行./rieszctl restart。当RIESZ_PASSWORD_HASH存在时，它优先于明文RIESZ_PASSWORD生效。
  • 启用两步验证：登录网页后打开「设置」→「安全」→「开始设置」，用手机上的验证器应用扫码并输入6位验证码，最后妥善保存页面显示的8个一次性恢复码。详见设置页。
  • 强制两步验证：在.env中设置RIESZ_REQUIRE_TOTP=true。开启后，在完成验证器绑定之前，登录后只能访问设置页，无法使用其他功能。
  • 丢失验证器：登录时改用之前保存的恢复码；如果恢复码也找不到了，在宿主机上执行./rieszctl reset-totp直接关闭两步验证。
  • 登出所有设备：在「设置」→「设备」里操作，或在宿主机上执行./rieszctl revoke-sessions。

登录接口带有失败限流：同一客户端IP在RIESZ_LOGIN_LOCKOUT_MINUTES分钟内连续失败达到RIESZ_LOGIN_MAX_FAILURES次后会被暂时锁定；如果所有IP的累计失败次数达到RIESZ_LOGIN_MAX_FAILURES_GLOBAL，整个站点的登录都会暂缓。

推送通知

RieszManager使用浏览器标准的Web Push推送消息：当你在某个浏览器里开启推送时，由该浏览器厂商的推送服务（Chrome为Google FCM、Firefox为Mozilla、Safari/iPhone为Apple）分配一个推送地址，backend容器在需要通知时把端到端加密后的消息直接发往这个地址。整个过程不需要注册任何第三方账号或API key，也不经过RieszManager作者的任何服务器，每个部署都使用自己生成的密钥。

部署侧需要满足的条件：

  • HTTPS：浏览器只在HTTPS站点（或本机127.0.0.1）下开放Web Push；RIESZ_PUBLIC_ORIGIN会被用作VAPID推送的联系地址。
  • 外网访问：backend容器随服务启动一个常驻任务监听runner事件，需要能访问外网HTTPS以连接各浏览器厂商的推送服务。
  • 签名密钥（VAPID）：.env中的RIESZ_VAPID_PRIVATE_KEY可以留空。留空时，第一次用到推送功能会自动生成密钥并保存在data/backend/vapid_private.pem（仅所有者可读）。如果日后更换或丢失了这把密钥，之前订阅过的所有设备都会失效，需要在「设置」里重新打开一次推送。
  • 客户端环境：Android手机需要能连接Google服务；iPhone需要iOS 16.4以上，并且必须先把网页「添加到主屏幕」、从主屏幕图标打开后才能订阅。

各设备上的开启方法与触发时机见使用指南：推送通知。

升级

拉取新代码后，依次更新runner和容器：

git pull
./rieszctl runner install     # 更新 runner 依赖；服务已在运行时会平滑重载（不打断工作中的会话）
./rieszctl up                 # 重新构建并启动容器

备份

属于RieszManager自身、需要备份的只有两处：

  • .env：全部配置与密钥；
  • data/backend/：后端SQLite数据库（含两步验证密钥、登录会话与设备推送订阅）以及自动生成的vapid_private.pem推送签名密钥。如果这把密钥丢失，各设备需要在设置里重新开启推送。

对话记录本身由Claude Code保存在~/.claude/projects/下；网页端上传的附件保存在~/.local/state/riesz-manager/uploads/（超过30天会自动清理）。

安全说明

任何能登录RieszManager的人，都能以宿主机用户的身份让Claude执行命令、读写该用户有权访问的文件。请务必使用强密码并启用两步验证。

  • 网关绑定本机：gateway默认只监听127.0.0.1；不要把RIESZ_BIND改成0.0.0.0后直接暴露到公网，务必在前面放置TLS终端。
  • Cloudflare IP头信任条件：RIESZ_TRUST_CF_HEADER=true只应在流量确实经由Cloudflare转发、且网关只监听本机时开启；否则客户端可以伪造CF-Connecting-IP请求头，绕过按IP的登录限流。
  • runner通信隔离：runner只监听Unix socket（目录权限0750，socket文件权限0660），并且每次请求都会校验RUNNER_TOKEN。
  • 项目文件只读与路径限制：网页中的项目文件浏览器以只读方式提供文件，路径会解析符号链接并严格限制在当前项目目录内；下载或查看原始文件时响应带有Content-Security-Policy: sandbox，不会在本站源下执行脚本。
  • HTML渲染预览隔离：预览HTML文件时通过/api/view/<令牌>/<路径>加载。令牌是带签名的只读凭证，只对单个项目有效、一小时后过期；响应头带Content-Security-Policy: sandbox（不含allow-same-origin），因此页面内的脚本运行在匿名来源中，拿不到本站的Cookie、本地存储或API权限。不过被预览的页面仍可以加载外部网络资源，因此它最多能读到并外发的是该项目目录内的其他文件。
  • 推送内容加密：Web Push负载使用浏览器端生成的密钥做端到端加密，途经的浏览器厂商推送服务看不到通知正文。
  • 套餐用量查询：莉思玩偶显示的套餐用量来自runner定期在本地执行的claude -p /usage，这是Claude Code的内置命令，不调用模型、不消耗额度，也不会留下会话记录。

排错

现象处理
页面提示「宿主机运行器未连接」执行./rieszctl runner status查看服务是否运行；确认.env里的RUNNER_SOCKET_DIR是绝对路径且与runner一致；确认RIESZ_UID/RIESZ_GID与运行runner的宿主机用户相同。
登录后立即掉线 / 报CSRF失败RIESZ_PUBLIC_ORIGIN必须与浏览器地址栏里的访问地址完全一致（协议+域名+端口，末尾不要带斜杠）。修改后执行./rieszctl restart。
WebSocket连不上检查前面的反向代理是否转发了Upgrade和Connection请求头，参考已有的nginx配置。
新会话启动失败执行./rieszctl runner logs查看报错；在同一宿主机用户的终端里运行claude -p "hi"，确认Claude Code本身已登录且能正常回复。
语音按钮不可用浏览器只在HTTPS（或localhost）下允许网页使用麦克风；另外如果未配置OPENAI_API_KEY，则依赖浏览器自带的语音识别能力。

卸载

停止容器并移除宿主机上的runner用户服务：

./rieszctl down
./rieszctl runner uninstall

如果你不再需要保留配置和运行数据，可以接着删除：

  • 仓库目录里的data/和.env（或直接删除整个仓库目录）；
  • ~/.local/state/riesz-manager（存放上传的附件、输入历史等runner状态）。

所有会话记录都保存在~/.claude/projects/下，属于Claude Code本身的数据，卸载RieszManager不会删除它们。

RUNNER_MAX_FILE_BYTES2097152文件查看器中允许显示的最大文件大小（字节）

OPENAI_API_KEY空配置OpenAI兼容的API key后，录音会在服务端转写；留空则在支持的浏览器上使用浏览器内置的语音识别
OPENAI_BASE_URLhttps://api.openai.com/v1OpenAI兼容接口的基础URL
RIESZ_TRANSCRIBE_MODELgpt-4o-transcribe服务端语音转写使用的模型
RIESZ_TRANSCRIBE_LANGUAGE空（注释示例为zh）语音转写的语言代码

变量默认值说明
RIESZ_MAX_UPLOAD_MB100上传附件的最大大小（MB）
RIESZ_DEBUGfalse是否开启调试模式

推送通知（可选）

变量默认值说明
RIESZ_VAPID_PRIVATE_KEY空用于签名Web Push消息的私钥（PEM格式，或base64url编码的原始私钥）。留空时会在首次使用时自动生成并保存在data/backend/vapid_private.pem。更换此密钥会使所有设备已有的推送订阅失效，需要重新在设置中开启
